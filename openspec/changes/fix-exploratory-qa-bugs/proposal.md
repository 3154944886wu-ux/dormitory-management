# Proposal: 收口探索式测试发现的跨模块逻辑缺口

## Why

全链路探索测试暴露了归寝请假状态机、入住人数、调宿/选宿、权限范围与检查计划等交叉缺陷，会在乱序、销假、换宿、降权等非常规路径下破坏数据一致性。

## What Changes

- 请假仅已批准覆盖未归；批准按归寝窗覆盖且不改写已归；销假清理未发生日请假打卡；非在住不可请假
- 未归生成必须过截止时间；跨午夜 00:30 窗口在 00:05 不得锁死打卡
- 入住计数在写入学生后同步；选宿确认置 `status=1`；待入住可分房
- 强制调宿取消在途申请；同房换床豁免满员；执行 CAS；MIXED 匹配共享预留；室友组可变空列表并按房间容量
- 范围判断改用 Security 角色；检查计划写接口与列表按范围；记录校验计划状态与唯一房间；完成前检查待整改
- 报修须处理中才能完成；水电缴费只能走 `/pay`；`init-admin` 不再重置已有密码
- 异常鉴权使用打卡时房间快照；前端打卡规则、报修关闭、重匹配次数、学生状态文案对齐

## Out of Scope

- 不把水电改成按人计费账本（仍按房间月度账单，仅禁止假缴费）
- 不引入消息队列与分布式锁中间件
