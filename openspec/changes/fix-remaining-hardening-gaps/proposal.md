# Proposal: 收口剩余加固缺口

## Why

上一轮修掉了选宿误报、室友、上传鉴权与登录踢出。对照代码仍有：学生宿舍详情字段空白、宿管范围 SQL 交叉误伤、请假审批越权、改密不校验原密码、分页除零、匹配失败文案重复、注册枚举学号、学生可扫全校房间。

## What Changes

- 学生档案 JOIN 回写楼层/房型/入住人数；首页待办拉取请假与报修
- 打卡默认兜底为待打卡；工作台水电拆分与报修已关闭计数
- 宿管范围改为「每条范围 AND、范围之间 OR」的 JSON_TABLE 匹配；请假审批/异常处理/打卡搜索按范围校验
- 学生不可列全校房间与空床；本房间检查记录允许学生提交整改
- `/users/me` 不再接受明文密码；资料页改密走 `/auth/password` 并要求原密码
- 注册失败统一文案；批次/选宿接口 HTTP 状态与 JSON `code` 对齐
- `pageSize<=0` 回落到默认分页；异常表唯一键；楼栋 name 唯一；匹配 CAS 防并发

## Out of Scope

- 不重写 `dormitory.sql` 全量 dump；黄金路径仍是 `schema.sql` + migrations
- 不删除未挂路由的 `CheckException.vue` / `Home.vue`（避免误伤），真实入口保持 `ManagerExceptions.vue`

## 验收标准

- 学生「我的宿舍」展示楼层、房型、入住人数
- 多范围宿管看不到交叉乘积数据，也不能审批范围外请假
- 学生 token 访问 `GET /api/rooms` 为 403
- 空批次触发匹配文案只有一层「匹配失败」
- `pageSize=0` 不再 500
